# Фарм зонтиков Яндекс Погоды

Приложение на Node.js для автоматического фарма зонтиков в Яндекс Погоде. Отправляет отчёты о погоде и отслеживает прогресс коллекции без запуска браузера на сервере.

## Требования

- Node.js 22+ и npm
- Windows, Linux или macOS
- Аккаунт Яндекса
- Установленный Google Chrome, Microsoft Edge или Chromium для авторизации
- Docker и Docker Compose для контейнерного развёртывания (опционально)

## Установка

1. Клонировать репозиторий:

   ```sh
   git clone https://github.com/Murkless/YaUmbFarm.git YaUmbFarm
   cd YaUmbFarm
   ```

2. Установить зависимости:

   ```sh
   npm ci
   ```

3. Создать файл конфигурации:

   ```sh
   cp config.example.json config.json
   ```

   При обновлении существующей установки файл `config.json` перезаписывать не требуется.
   Команды приведены для POSIX shell или PowerShell, где `cp` является псевдонимом `Copy-Item`.

4. Выполнить авторизацию в Яндексе:

   ```sh
   npm run login
   ```

   После входа в открывшемся браузере необходимо вернуться на страницу Яндекс Погоды и нажать Enter в терминале. Cookies сохраняются в `.private/session.json`. Пароль приложение не хранит.

   Для нестандартной установки можно указать путь к исполняемому файлу через `WEATHER_BROWSER_PATH`. Например, в PowerShell:

   ```powershell
   $env:WEATHER_BROWSER_PATH = 'C:\Program Files\Microsoft\Edge\Application\msedge.exe'
   npm run login
   ```

   В Linux, например для Chromium из `/usr/bin`:

   ```sh
   WEATHER_BROWSER_PATH=/usr/bin/chromium npm run login
   ```

   В macOS путь может указывать на исполняемый файл внутри `.app`, например `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`.

   Поддерживаются браузеры с Chrome DevTools Protocol. Firefox и Safari для этого способа входа не поддерживаются; выбор браузера по умолчанию в ОС не влияет на автоматический поиск.

## Настройка

Параметры приложения задаются в `config.json`:

```json
{
  "pageUrl": "https://yandex.ru/pogoda/ru",
  "checkIntervalSeconds": 600,
  "afterReportSeconds": 600,
  "answer": "random",
  "sessionFile": ".private/session.json",
  "stateFile": ".private/state.json"
}
```

- `pageUrl`: адрес страницы Яндекс Погоды для выбранного местоположения.
- `checkIntervalSeconds`: интервал проверки недоступной формы отчёта, в секундах.
- `afterReportSeconds`: пауза после попытки отправки, в секундах.
- `answer`: случайный ответ (`random`), подтверждение прогноза (`confirm`) или точный текст доступного варианта.
- `sessionFile` и `stateFile`: пути к файлам сессии и состояния.

По умолчанию оба интервала составляют **10 минут**. Ограничения сервера могут увеличивать время ожидания.

## Использование

Проверка авторизации, местоположения и доступности формы:

```sh
npm run status
```

Запуск постоянного фарма:

```sh
npm start
```

Выполнение одной попытки:

```sh
npm run once
```

Статус `CREDITED` означает увеличение счётчика отчётов. При `AUTH_REQUIRED` требуется повторная авторизация, при `REGION_MISMATCH` необходимо проверить место наблюдения.

Выбор города в `pageUrl` не устанавливает место наблюдения. Для его изменения предусмотрена команда `node src/cli.mjs locate LAT LON ACCURACY_METERS`, где точность задаётся в пределах от 1 до 2000 метров. После изменения необходимо повторно выполнить `npm run status`.

## Запуск через Docker

Авторизация выполняется локально до развёртывания. Файлы `config.json` и `.private/session.json` необходимо перенести на сервер через SSH или SFTP.

Создать `.env` на основе примера:

```sh
cp .env.example .env
ls -ldn .private
```

Значения `WEATHER_UID` и `WEATHER_GID` должны совпадать с владельцем каталога `.private` на сервере:

```dotenv
WEATHER_UID=1000
WEATHER_GID=1000
WEATHER_CONFIG_HOST=./config.json
```

Файлы конфигурации и сессии должны быть доступны указанному UID для чтения. Для каталога `.private` используются права `0700`, для файлов сессии и состояния — `0600`.

Собрать образ и проверить сессию:

```sh
docker compose build
docker compose run --rm --no-deps weather node src/cli.mjs status
```

После получения статуса `READY` запустить приложение:

```sh
docker compose up -d
docker compose logs -f --tail=100 weather
```

Браузер в контейнер не включён. Сессия и состояние сохраняются в каталоге `.private` на сервере. Перед выполнением дополнительных команд с той же сессией необходимо остановить службу. Политика перезапуска допускает до трёх быстрых повторных запусков после ошибки; после перезагрузки Docker требуется повторно выполнить `docker compose up -d`.


## Ограничения

Проект неофициальный и использует внутренние вызовы Яндекс Погоды. Поведение сервера, условия начисления наград и срок действия сессии могут изменяться. Отправка с авторизованного аккаунта, минимальный допустимый интервал и работа сессии в течение нескольких недель пока не подтверждены. Случайные ответы не являются реальными наблюдениями и могут влиять на данные об осадках.
